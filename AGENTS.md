# AGENTS.md

For coding agents working in this repository. This file is an index and a list of traps: it holds only what no
check, tool, or code can tell you ([ADR-0000](docs/adr/0000-record-architecture-decisions.md)).

This repository builds the native mobile clients of **mycroblog**: iOS under `app/ios` (Swift, SwiftUI) and Android
under `app/and` (Kotlin, Jetpack Compose). What both share lives under `shared/` as sources and generators, not as
runtime code. The server, `my`, lives in [mycroblog/my](https://github.com/mycroblog/my), checked out next to this
repository as `../my`.

## The path

One path takes a change from an issue to `main`; each step is a command of `scripts/kit` that refuses what must not
pass and says the fix (`scripts/kit help`).

1. `scripts/kit issue claim <n> --plan "<one line>"`, then `scripts/kit ctx <n>` for the issue, what it depends on,
   and the ADRs it cites.
2. Work in a worktree, on one branch per goal, `<type>/<issue>-<slug>`.
3. Ask `ios-platform-advisor` or `android-platform-advisor` before relying on how the OS behaves.
4. `scripts/kit check`, then `scripts/kit pr open`, then `scripts/kit pr land <pr>`.

## Traps

- **Never weaken a check to make a change pass.** Change the code.
- **Build only what was asked.** No document, ADR, screen, setting, or option because it might be useful.
- **Never copy code, translations, or UI strings from `../my`.** The server is AGPL-3.0 and this repository is
  Apache-2.0; only the parts that my ADR-0093 §2 licenses as MIT may be reused, and today that is the API specification ([ADR-0001](docs/adr/0001-license.md) §3).
- **A gap in the server goes to `mycroblog/my` as an issue**, not around it in the client.
- **A feature lands on iOS and Android in the same pull request, but the screens do not look alike**: features,
  behavior, and content match; layout, components, and interaction follow the Human Interface Guidelines and
  Material Design 3 ([ADR-0002](docs/adr/0002-platforms-and-layout.md) §4, §6).
- **Decide what is cheap to undo, and say so in the pull request. Ask only for what is expensive to undo** and that
  no Accepted ADR covers. Only the decider sets an ADR to `Accepted` or `Rejected`.
- **Boy scout rule**: never leave something broken because it is outside your issue. Fix it in a commit of its own
  and say so in the pull request, or file an issue (in `mycroblog/my` when it is the server's).
- **Every file describes the present.** Why something changed goes in the commit message and the pull request.
- Code, comments, commit messages, and pull request titles are in English; commits follow Conventional Commits and
  name their issue (`feat(ios): add home timeline (#12)`). Design documents are in Japanese.
- Never commit secrets or credentials (signing keys, APNs and FCM credentials, provisioning profiles).

## Changing these instructions

Do not edit this file to record a lesson. Propose the line in the pull request; the decider adds it when it is
non-obvious, has happened repeatedly, and is specific enough to act on. Anything a check can enforce becomes a check
instead.
