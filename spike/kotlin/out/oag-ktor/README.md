# social.mycroblog.api - Kotlin client library for my client API

The client API of my, an ActivityPub microblog server. It is not compatible with the
Mastodon client API.

- Every error is an RFC 9457 problem document (`application/problem+json`) whose `title`
  and `detail` are localized from `Accept-Language`. Clients branch on `type` and `status`,
  never on the text.
- Requests authenticate with an OAuth 2.0 access token in `Authorization: Bearer`, never
  with cookies. Each operation lists the scopes it needs under `security`; a broad scope
  (`read`, `write`, `follow`, `admin`) grants the fine-grained scopes under it. A missing or
  invalid token is a 401 with `WWW-Authenticate`, a token without the scope a 403
  `insufficient_scope`.
- The operations carry the `RateLimit` and `RateLimit-Policy` fields
  (draft-ietf-httpapi-ratelimit-headers): anonymous requests share a limit per client IP,
  authenticated requests one per account, and an administrator may cap one client across
  all its users (the `client` policy). Past a limit the answer is 429 with `Retry-After`.
  The fields are left out while the server cannot read its limits, which then let requests
  through.
- Every write (`POST`, `PUT`, `PATCH`, `DELETE`) takes an `Idempotency-Key`, with which
  a request whose answer did not arrive is sent again and carried out once. The few
  whose answer carries a secret take none (`x-no-idempotency-key` says why).
- This document is served at `GET /openapi.yaml`, without a limit or a token.
- IDs are UUIDv7 strings. Collections use keyset pagination: pass the `next_cursor` of a
  page as `cursor` to get the next page.

## Documentation for Authorization


Authentication schemes defined for the API:
<a id="oauth2"></a>
### oauth2

- **Type**: OAuth
- **Flow**: accessCode
- **Authorization URL**: /oauth/authorize
- **Scopes**: 
  - admin: Administer the instance, as far as the user&#39;s roles allow (first-party clients only).
  - admin:read: Read the instance&#39;s administration data, as far as the user&#39;s roles allow (first-party clients only).
  - admin:write: Change the instance&#39;s administration data, as far as the user&#39;s roles allow (first-party clients only).
  - admin:manage_reports: Use the permission manage_reports of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_accounts: Use the permission manage_accounts of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_domains: Use the permission manage_domains of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_rules: Use the permission manage_rules of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_settings: Use the permission manage_settings of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_invites: Use the permission manage_invites of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:view_audit: Use the permission view_audit of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_jobs: Use the permission manage_jobs of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_custom_emojis: Use the permission manage_custom_emojis of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_webhooks: Use the permission manage_webhooks of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_announcements: Use the permission manage_announcements of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_finance: Use the permission manage_finance of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_supporters: Use the permission manage_supporters of the user&#39;s roles (tokens the user issues to themselves only).
  - admin:manage_errors: Use the permission manage_errors of the user&#39;s roles (tokens the user issues to themselves only).
  - read: Read everything the user can read.
  - write: Change everything the user can change.
  - follow: Read and change follows, blocks, and mutes.
  - push: Receive Web Push notifications.
  - read:accounts: Read accounts and their followers and follows, and the user&#39;s own account with its roles and permissions, preferences (including whether emails still reach the address), notification settings and policy, aliases, automatic deletion policy, and private notes on accounts.
  - read:blocks: Read the accounts the user blocks.
  - read:bookmarks: Read the user&#39;s bookmarks.
  - read:custom_emojis: Read the custom emoji the user made and their requests for new ones.
  - read:direct: Read the direct posts the user sends and receives and their conversations (&#x60;read:statuses&#x60; does not show them).
  - read:events: Read the events the user sees, their attendees, and the invitations of the events the user organizes.
  - read:favourites: Read the posts the user favourited.
  - read:filters: Read the user&#39;s keyword filters.
  - read:finance: Read the totals of the instance&#39;s costs and income, as far as the user&#39;s roles allow.
  - read:follows: Read follows, follow requests, lists, followed hashtags, and the accounts whose new posts notify the user.
  - read:mutes: Read the accounts and domains the user mutes.
  - read:notifications: Read the user&#39;s notifications and the notification requests.
  - read:reports: Read the reports the user filed and whether they are resolved.
  - read:statuses: Read posts and timelines.
  - read:supporters: Read the user&#39;s own supporter subscription.
  - read:voice: Read the voice chat rooms the user sees.
  - write:accounts: Change the user&#39;s profile, featured hashtags, preferences, notification settings and policy, badges, supporter listing, and private notes on accounts.
  - write:blocks: Block and unblock accounts.
  - write:bookmarks: Bookmark posts and remove bookmarks.
  - write:custom_emojis: Request new custom emoji, and change and delete the ones the user made.
  - write:events: Create, change, and cancel events, answer them, approve their attendees, invite to them, and name their co-organizers.
  - write:favourites: Favourite posts and react to them with emoji, and take both back.
  - write:filters: Create, change, and delete the user&#39;s keyword filters.
  - write:follows: Follow and unfollow accounts and hashtags, answer follow requests, change lists, and subscribe to the new posts of accounts.
  - write:media: Upload media, read their state while they process, and change their descriptions.
  - write:mutes: Mute and unmute accounts, domains, and threads.
  - write:notifications: Mark notifications read and dismiss them, and accept and dismiss the notification requests.
  - write:reports: Report accounts and posts to the moderators.
  - write:statuses: Post, edit, delete, boost, and pin posts, vote in polls, and set who may quote a post.
  - write:supporters: Subscribe to the supporter plans, and change, cancel, and resume the subscription (first-party clients only).
  - write:voice: Open, join, and leave voice chat rooms, and host them.
