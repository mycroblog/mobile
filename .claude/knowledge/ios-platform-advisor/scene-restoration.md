# Scene restoration and tab accessibility

- SceneStorage: restored value is per Scene; system gives no guarantee when or how often it persists; destroyed when the scene is explicitly destroyed (iPadOS: switcher snapshot discarded) -> a new scene session starts empty [https://developer.apple.com/documentation/swiftui/scenestorage.md, checked 2026-11-27]
- Apple engineer: after termination the system restores iPad scenes via UISceneSession.stateRestorationActivity, and UISceneActivationConditions can stop a scene from being restored (Apple forums) [https://developer.apple.com/forums/thread/702040, checked 2026-11-27]
- Unanswered forum report: iPadOS restores the number of windows, not their kind (undocumented) [https://developer.apple.com/forums/thread/728193, checked 2026-11-27]
- Scene.restorationBehavior(_:) iOS 18, .disabled opts a scene out of restore; Scene.defaultLaunchBehavior has no iOS or iPadOS availability (macOS 15, visionOS 26) -> neither carries state into a new scene [https://developer.apple.com/documentation/swiftui/scene/restorationbehavior(_:), https://developer.apple.com/documentation/swiftui/scene/defaultlaunchbehavior(_:), checked 2026-11-27]
- Tab has init(value:content:label:) taking a Label view; Apple's pages say nothing on how a tab item's spoken name is derived [https://developer.apple.com/documentation/swiftui/tab.md, checked 2026-11-27]
- Each scene saves state itself, "determines the best opportunities to ask for the current state"; the system asks the delegate "before disconnecting a scene" -> no documented trigger such as sceneDidEnterBackground; Apple's sample fills the activity when the scene becomes inactive [https://developer.apple.com/videos/play/wwdc2025/282/, https://developer.apple.com/documentation/uikit/uiscenesession/staterestorationactivity, https://developer.apple.com/documentation/uikit/restoring-your-app-s-state, checked 2026-11-27]
- A scene not frontmost stays foregroundActive while it can take input; foregroundInactive only on a system interruption (Control Center, alert, Siri, App Switcher, another app's window covering it in windowed apps); save view state by ActivationState [https://developer.apple.com/documentation/uikit/uitraitcollection/activeappearance, checked 2026-11-27]
- Scenes go to background "when someone dismisses your app's UI"; UIKit may disconnect a background or suspended scene any time [https://developer.apple.com/documentation/uikit/managing-your-app-s-life-cycle, checked 2026-11-27]
- Jetsam: `vm-pageshortage` frees background process memory for the foreground app; `per-process-limit` makes any app eligible, foreground included; no page says a visible windowed scene is spared or targeted [https://developer.apple.com/documentation/xcode/identifying-high-memory-use-with-jetsam-event-reports, checked 2026-11-27]
- SceneStorage "works very similar to State", shared by all SceneStorage in the scene, keep it lightweight; no page says where in the view lifecycle to write or read it [https://developer.apple.com/documentation/swiftui/scenestorage, checked 2026-11-27]
- TextField on iOS uses the prompt or the label as placeholder depending on the initializer; no page says how its accessibility label is derived [https://developer.apple.com/documentation/swiftui/textfield, checked 2026-11-27]
- UISceneSession.userInfo is per session; UIApplication.openSessions lists active and archived sessions; no page describes one scene restoring another session's state -> share through app-level storage (undocumented as a pattern) [https://developer.apple.com/documentation/uikit/uiapplication/opensessions, https://developer.apple.com/documentation/uikit/uiscenesession, checked 2026-11-27]
