# Associated domains, Universal Links, ASWebAuthenticationSession

- AASA is `https://<fqdn>/.well-known/apple-app-site-association`, no extension, valid certificate, no redirects; each subdomain needs its own file and entitlement entry -> serve a 200 directly [https://developer.apple.com/documentation/xcode/supporting-associated-domains, checked 2026-11-27]
- Since iOS 14 devices fetch AASA from an Apple CDN, not your server; the CDN requests the file within 24 hours and devices recheck about weekly -> a fresh or fixed domain is not instantly visible [https://developer.apple.com/documentation/xcode/supporting-associated-domains, checked 2026-11-27]
- `<service>:<fqdn>?mode=developer` bypasses the CDN and reads your server; only apps signed with a development profile, only devices in developer mode, user opt-in per device; any valid TLS cert is accepted; modes are developer, managed, developer+managed -> use for a tunnel host, never ship it [https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.associated-domains, checked 2026-11-27]
- Adding the Associated Domains capability in Xcode adds the entitlement and the feature to the app ID -> needs a Team that can register the App ID [https://developer.apple.com/documentation/xcode/supporting-associated-domains, checked 2026-11-27]
- `Callback.https(host:path:)` (iOS 17.4+): the host must be a member of a domain associated with the app [https://developer.apple.com/documentation/authenticationservices/aswebauthenticationsession/callback/https(host:path:), checked 2026-11-27]
- HTTPS callback requires the `webcredentials` service (entitlement and AASA `webcredentials.apps`), not `applinks`; failure is `WebAuthenticationSession` Code=1 "not associated with domain ... requires Associated Domains using the webcredentials service type" [https://developer.apple.com/forums/thread/763621 (error text, developer post) and https://developer.apple.com/forums/thread/838975 (Apple DTS), checked 2026-11-27]
- `?mode=developer` bypasses the CDN and the device cache; to return to the CDN remove it and raise the build number, then install over the existing build; production verification happens at install or update only; a failed CDN scrape stays cached (wrong content type, redirect, bad JSON) [https://developer.apple.com/forums/thread/838975 (Apple forums), checked 2026-11-27]
- Tapping a universal link in Safari on the same domain stays in Safari; a link on another domain opens the app -> test Universal Links from Notes or Messages, not from a page on the same host [https://developer.apple.com/documentation/xcode/allowing-apps-and-websites-to-link-to-your-content, checked 2026-11-27]
