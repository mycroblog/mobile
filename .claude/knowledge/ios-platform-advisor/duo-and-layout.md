# Duo and layout

- iPhone Duo: Apple's first foldable iPhone, sold from 2026-10-23, ships iOS 27.1; book fold, 5.4" outer and 7.6" inner display, open it is wider than tall -> plan for both displays [https://www.apple.com/newsroom/2026/09/apple-unveils-iphone-duo/, https://support.apple.com/en-us/148588, checked 2026-11-27]
- Outer display portrait: compact width, regular height; outer landscape: compact/compact; inner: regular/regular -> layout by size class [https://developer.apple.com/videos/play/tech-talks/111461/, checked 2026-11-27]
- Apps built with the iOS 27 SDK resize live between the displays; apps built with Xcode 26 or earlier run inset with empty space -> build with the latest Xcode [https://developer.apple.com/iphone-duo/prepare/, checked 2026-11-27]
- Fold and unfold is a trait and size change, not a scene disconnect (Apple forums); Apple's docs say only that content transitions -> still save and restore state on every change [https://developer.apple.com/forums/thread/847644, checked 2026-11-27]
- The inner display ignores supported orientations; in iOS 27 idiom and orientation are no longer meaningful for layout -> never branch on them [https://developer.apple.com/videos/play/tech-talks/111461/, https://developer.apple.com/videos/play/wwdc2026/278/, checked 2026-11-27]
- Multiple windows of one app on the Duo's inner display only; Split View on the inner display; window sizes come from pose and Split View -> support multiple scenes [https://developer.apple.com/videos/play/tech-talks/111464/, checked 2026-11-27]
- On the outer display and the inner display in landscape the system puts tab bar and toolbar vertically on one edge; in a split view only the detail column's bars; title-only items stay horizontal, custom views only with opt-in -> give items an icon and a title [https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo, https://developer.apple.com/videos/play/tech-talks/111462/, checked 2026-11-27]
- HIG: do not reinvent the app when it resizes; show one more level of hierarchy on the inner display; keep navigation containers outside arrangement views -> list-detail in regular width [https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo, checked 2026-11-27]
- First iOS of: NavigationSplitView 16, sidebarAdaptable 18, defaultTabBarPlacement/presentationPlacement/visibilityPriority/ToolbarOverflowMenu 27.0, ArrangementView/ReservedRegion/toolbarVerticalEdge/axisBehavior 27.1 -> gate 27.x APIs on a minimum of 26 [https://developer.apple.com/documentation/swiftui/, checked 2026-11-27]
- Hinge state and angle (onHingeChange) are for effects, not layout; the only outer-display scene accessory is CameraCaptureAccessory for camera apps [https://developer.apple.com/videos/play/tech-talks/111464/, checked 2026-11-27]
- iPadOS 26: resizing, rotation and window layout all change the scene's size; each scene saves and restores its own UI state; UIRequiresFullScreen is deprecated [https://developer.apple.com/videos/play/wwdc2025/282/, checked 2026-11-27]
- SceneStorage is per scene, destroyed with it, timing not guaranteed, not for large or sensitive data; NavigationPath.codable serializes a Codable stack -> store route values only [https://developer.apple.com/documentation/swiftui/scenestorage, https://developer.apple.com/documentation/swiftui/navigationpath, checked 2026-11-27]
