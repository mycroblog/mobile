# Timeline list, scroll position, GRDB, defaults

- GRDB 7.12.0 is latest (Nov 2026); needs Swift 6.1+, Xcode 16.3+, iOS 13+; Swift Package Index lists builds for Swift 6.1-6.4 on iOS; README claims zero data race safety errors [https://github.com/groue/GRDB.swift/releases, https://swiftpackageindex.com/groue/GRDB.swift, https://github.com/groue/GRDB.swift#requirements, checked 2026-11-28]
- GRDB: observe with `for try await v in ValueObservation.tracking{}.values(in: writer)`; async reads/writes honor cancellation and roll back; DatabasePool = WAL, parallel reads; DatabaseQueue if unsure; Swift 6 flags non-Sendable records [https://github.com/groue/GRDB.swift/blob/master/GRDB/Documentation.docc/Concurrency.md, .../SwiftConcurrency.md, checked 2026-11-28]
- GRDB docs name no location for an app-only database (only App Group for shared) -> Application Support; Caches/tmp are purgeable and excluded from backup, so re-creatable timeline data may go there; isExcludedFromBackup for the rest [https://developer.apple.com/documentation/foundation/optimizing-your-app-s-data-for-icloud-backup, checked 2026-11-28]
- ScrollPosition (iOS 18+) + scrollTargetLayout on a LazyVStack/VStack in a ScrollView: viewID updates with the top-most id; scrollTo(id:anchor:), scrollTo(y:); SwiftUI keeps the id'd view visible on reorder/resize; a point is not kept when content changes; ids may be set before first layout -> save id, restore via scrollTo(id:) [https://developer.apple.com/documentation/swiftui/scrollposition, https://developer.apple.com/documentation/swiftui/view/scrollposition(id:anchor:), checked 2026-11-28]
- No page read gives an id+offset restore API or a List vs LazyVStack recommendation; scrollTargetLayout is documented with lazy stacks and VStack, scrollPosition(id:) examples use ScrollView (List not shown) [same pages, checked 2026-11-28]
- refreshable(action:) iOS 15+: on List gives pull-to-refresh, indicator shown until the async action returns [https://developer.apple.com/documentation/swiftui/view/refreshable(action:), checked 2026-11-28]
- UserDefaults: for non-sensitive settings, thread-safe, unencrypted, in device backup; sensitive data goes in Keychain; required-reason API -> declare in PrivacyInfo.xcprivacy: NSPrivacyAccessedAPITypes entry NSPrivacyAccessedAPICategoryUserDefaults with reason `CA92.1` (read/write info only the app itself can access; `1C8F.1` is for App Group); the file sits at the root of the iOS app bundle, i.e. a resource of the app target; XcodeGen puts non-source files in Copy Bundle Resources by default (its source, not Apple's) [https://developer.apple.com/documentation/foundation/userdefaults, https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype, https://developer.apple.com/documentation/bundleresources/adding-a-privacy-manifest-to-your-app-or-third-party-sdk, https://github.com/yonaskolb/XcodeGen/blob/master/Sources/XcodeGenKit/SourceGenerator.swift, checked 2026-11-28]
