# Cross-process locks and shared tokens

- 0xdead10cc: terminated for holding a file lock or SQLite lock during suspension (TN2151 wording, quoted by a developer) -> release before the process is eligible for suspension [https://developer.apple.com/forums/thread/728957, checked 2026-11-27]
- Quinn: holding file locks while suspended triggers 0xdead10cc; "app" means app or app extension; since iOS 14 the check is exact; iOS 14.0b7+ only forgives the kill, the lock can still hang other processes -> avoid file locks [https://developer.apple.com/forums/thread/655225, checked 2026-11-27] (Apple forums)
- Quinn: wrap lock-holding work in a UIApplication background task so the app is not suspended until it ends or expires; a task is only safe to begin in the callback that woke the app (Kevin Elliott, DTS) [https://developer.apple.com/forums/thread/126438, checked 2026-11-27] (Apple forums)
- Quinn: a lock shared between processes is unsafe on iOS (other side may not run or may be suspended while holding it); use rename for atomic replace, Darwin notifications to wake the other side, SQLite/Core Data for locks [https://developer.apple.com/forums/thread/755758, checked 2026-11-27] (Apple forums)
- App Extension guide: NSFileCoordinator is allowed from iOS 9 but NSFilePresenters must be removed when the extension goes to the background; "Use Core Data, SQLite, or Posix locks" and synchronize shared-container access [https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionScenarios.html, checked 2026-11-27]
- Extensions: no sharedApplication (so no beginBackgroundTask), no long-running background tasks; Quinn: use ProcessInfo.performExpiringActivity to stay unsuspended for short work; after completeRequest the system may terminate the extension at any time [https://developer.apple.com/forums/thread/76659, https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionOverview.html, checked 2026-11-27]
- performExpiringActivity: block runs with expired false while it holds a task assertion; a second call with expired true means stop now [https://developer.apple.com/documentation/foundation/processinfo/performexpiringactivity(withreason:using:), checked 2026-11-27]
- Quinn: SecItem APIs are "atomic" and thread safe in-process; not documented, nothing on multiple processes; kSecValueData in an update is the new value, not a match -> no documented cross-process compare-and-swap [https://developer.apple.com/forums/thread/117092, https://developer.apple.com/forums/thread/724023, checked 2026-11-27] (Apple forums)
- Keychain: App Group names work as access group names without the keychain-access-groups entitlement; kSecAttrSynchronizable absent means non-synchronizable items only; an item with a ThisDeviceOnly accessibility is not migrated to another device; AfterFirstUnlock is for background access [https://developer.apple.com/documentation/security/sharing-access-to-keychain-items-among-a-collection-of-apps, https://developer.apple.com/documentation/security/ksecattrsynchronizable, https://developer.apple.com/documentation/security/restricting-keychain-item-accessibility, checked 2026-11-27]
