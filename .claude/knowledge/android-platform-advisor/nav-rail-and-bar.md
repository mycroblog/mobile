# Navigation rail and bar details (checked 2026-11-27)

- NavigationRail is a fillMaxHeight Column with windowInsetsPadding(systemBarsForVisualComponents Vertical+Start) and spacedBy; no scroll, no custom Layout; NavigationSuiteScaffoldLayout measures navigationSuite in a Box with loose constraints (min 0, max = window) and places it at (0,0) -> source predicts a weight+verticalScroll Column inside works, a report says it did not (unresolved); the insets are zero if an ancestor consumed them [https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-compose-material3-release/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/NavigationRail.kt, .../NavigationSuiteScaffold.kt, release branch, 2026-11-27]
- NavigationRailDefaults.windowInsets = systemBarsForVisualComponents.only(Vertical + Start); NavigationRail applies it with windowInsetsPadding on its Column [NavigationRail.kt release branch, 2026-11-28]
- NavigationBarItem sizes itself by icon plus label height and measures the label with loose width: a wrapped label raises that item and moves its icon up; one-line labels keep icons level; alwaysShowLabel=false centers unselected icons [https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-compose-material3-release/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/NavigationBar.kt, 2026-11-27]
- Material Components labelVisibilityMode AUTO = labeled up to 3 items, selected-only from 4; labels one line by default (labelMaxLines); SELECTED and UNLABELED modes exist [https://raw.githubusercontent.com/material-components/material-components-android/master/docs/components/BottomNavigation.md, 2026-11-27]
- NavigationRail KDoc: "three to seven app destinations"; WideNavigationRail collapsed "three to seven", expanded "at least three"; no KDoc rule for more than seven -> 9 destinations are outside both ranges [https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-compose-material3-release/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/WideNavigationRail.kt, NavigationRail.kt same dir, 2026-11-28]
- WideNavigationRail(modifier, state, shape, colors, header, windowInsets, arrangement, contentPadding, content), ModalWideNavigationRail (+hideOnCollapse, expandedHeaderTopPadding, expandedProperties), WideNavigationRailItem(selected, onClick, icon, label, railExpanded, ...), rememberWideNavigationRailState() (expand/collapse/toggle/snapTo) have no Experimental opt-in on the 1.5.0-line release branch; the Layout places items by Arrangement and does not scroll -> 9 items need your own scroll; expanded modal = overlay with scrim [WideNavigationRail.kt same URL, https://developer.android.com/jetpack/androidx/releases/compose-material3, 2026-11-28]
- Material Components NavigationRailView has app:scrollingEnabled (default false); m3.material.io rail guidelines are a JS page and could not be read: no confirmed M3 rule for more destinations than fit [https://raw.githubusercontent.com/material-components/material-components-android/master/docs/components/NavigationRail.md, 2026-11-28]
- Modifier.verticalScroll sets verticalScrollAxisRange semantics (scroll actions for TalkBack and UiAutomator); no known issue found, test on a device [https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-main/compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/Scroll.kt, 2026-11-28]
- m3.material.io navigation bar pages (guidelines, accessibility) cannot be fetched as text: M3 wording on truncation and font scale is unconfirmed [2026-11-27]
