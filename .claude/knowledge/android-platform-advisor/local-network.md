# Local network permission, Android 17 (checked 2026-11-27)

- targetSdk 37+: outgoing/incoming TCP and UDP on local network addresses need ACCESS_LOCAL_NETWORK, in every API incl. OkHttp and Cronet; blocked by default; targetSdk <37 gets it implicitly from INTERNET, and must not declare or request it [https://developer.android.com/privacy-and-security/local-network-permission, 2026-11-27]
- Local network = 169.254/16, 100.64/10, 10/8, 172.16/12, 192.168/16, IPv6 link-local and directly connected routes, multicast, 255.255.255.255, on Wi-Fi/Ethernet but not cellular or VPN; loopback is not listed (so not local network); 10.0.2.2 is in 10/8 [https://developer.android.com/privacy-and-security/local-network-definition.md.txt, 2026-11-27]
- ACCESS_LOCAL_NETWORK (API 37): protection level dangerous, group NEARBY_DEVICES (no new prompt if another NEARBY_DEVICES permission is granted); request at runtime with the system dialog [https://developer.android.com/reference/android/Manifest.permission.md.txt, 2026-11-27]
- Without it a TCP connect typically times out (no distinct exception, so OkHttp SocketTimeoutException); UDP and other denials give EPERM; NDK android_getnetworkblockedreason(fd) returns ANDROID_NETWORK_BLOCKED_REASON_LNP [https://developer.android.com/privacy-and-security/local-network-permission, 2026-11-27]
- Opt-outs: no network-security-config switch is documented; addresses from NsdManager resolve/DiscoveryRequest.FLAG_SHOW_PICKER need no permission; DNS to a local server on port 53 exempt [https://developer.android.com/privacy-and-security/local-network-permission, 2026-11-27]
- ActivityResultContracts.RequestPermission is androidx.activity 1.2.0+; the doc names Activity.requestPermissions() for the prompt [https://developer.android.com/reference/androidx/activity/result/contract/ActivityResultContracts.RequestPermission, 2026-11-27]
