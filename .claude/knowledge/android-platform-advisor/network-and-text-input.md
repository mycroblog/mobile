# Ktor on Android, cleartext, text fields, UI state (checked 2026-11-27)

- Ktor engines for Android: ktor-client-android (HttpURLConnection, no HTTP/2), ktor-client-okhttp (Android 5+, HTTP/2, WebSockets), ktor-client-cio (Android 7+); docs name no preferred engine, the mobile example uses OkHttp [https://ktor.io/docs/client-engines.html, 2026-11-27]
- HttpTimeout throws HttpRequestTimeoutException, ConnectTimeoutException or SocketTimeoutException; connect timeout unsupported on MockEngine [https://ktor.io/docs/client-timeout.html, 2026-11-27]
- Ktor 3.6.1 HttpRequestTimeoutException extends kotlinx.io.IOException [https://raw.githubusercontent.com/ktorio/ktor/3.6.1/ktor-client/ktor-client-core/common/src/io/ktor/client/plugins/HttpTimeout.kt, 2026-11-27]
- Ktor 3.6.1 OkHttp engine: OkHttp SocketTimeoutException becomes ConnectTimeoutException (message contains "connect") or Ktor SocketTimeoutException; every other IOException (e.g. UnknownServiceException) is rethrown unchanged [https://raw.githubusercontent.com/ktorio/ktor/3.6.1/ktor-client/ktor-client-okhttp/jvm/src/io/ktor/client/engine/okhttp/OkUtils.kt, 2026-11-27]
- Cleartext is off by default for targetSdk 28+; opt in per domain with <domain-config cleartextTrafficPermitted="true"><domain>..</domain>; includeSubdomains="true" matches subdomains too, otherwise exact match only; most specific domain wins [https://developer.android.com/privacy-and-security/security-config, 2026-11-27]
- Android 17 (API 37): with no config for localhost, an implicit one allows cleartext to localhost, ip6-localhost and numeric loopback IPs (127.0.0.1, [::1]) in every build; 10.0.2.2 is not loopback [https://developer.android.com/privacy-and-security/security-config, 2026-11-27]
- debug-overrides only adds trust anchors when debuggable; it has no cleartext attribute [https://developer.android.com/privacy-and-security/security-config, 2026-11-27]
- INTERNET and ACCESS_NETWORK_STATE go in the manifest; both normal permissions, no runtime request [https://developer.android.com/develop/connectivity/network-ops/connecting, 2026-11-27]
- Compose 1.13: value-based BasicTextField and M2 TextField deprecated for TextFieldState ones; M3 TextField/OutlinedTextField(state, label, placeholder, supportingText, isError, keyboardOptions, onKeyboardAction: KeyboardActionHandler, lineLimits); rememberTextFieldState saves across config change and process death; TextFieldState may be held in a ViewModel [https://developer.android.com/develop/ui/compose/text/user-input, 2026-11-27]
- KeyboardOptions(capitalization, autoCorrectEnabled: Boolean? = null, keyboardType, imeAction); autoCorrectEnabled applies to Text, Email, Uri types; Uri and Ascii samples use KeyboardCapitalization.None [https://developer.android.com/reference/kotlin/androidx/compose/foundation/text/KeyboardOptions, 2026-11-27]
- Hilt + Navigation 3: hiltViewModel() inside the entry with rememberViewModelStoreNavEntryDecorator(); doc shows hilt-lifecycle-viewmodel-compose 1.3.0 [https://developer.android.com/training/dependency-injection/hilt-jetpack, 2026-11-27]
- UI state: ViewModel survives config change not process death; saved state for small data such as text-field input; business-logic state in ViewModel with SavedStateHandle, UI-logic state with rememberSaveable [https://developer.android.com/topic/libraries/architecture/saving-states, 2026-11-27]
