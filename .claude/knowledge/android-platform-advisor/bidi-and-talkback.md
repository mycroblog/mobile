# Bidi text and TalkBack focus (checked 2026-11-28)

- androidx.core BidiFormatter.unicodeWrap(str) wraps text whose direction differs from the context in LRE/RLE+PDF plus a trailing (and, by default, leading) LRM/RLM mark; its docs say the isolate (FSI/PDI) form is not yet used; no HTML escaping; docs: use it on every text inserted into a localized message except machine-readable strings [https://developer.android.com/reference/androidx/core/text/BidiFormatter, https://developer.android.com/training/basics/supporting-devices/languages, 2026-11-28]
- Compose TextDirection values: Ltr, Rtl, Content (first strong char, else layout direction), ContentOrLtr, ContentOrRtl -> TextStyle(textDirection = Ltr) fixes a whole paragraph; it does not isolate a substitution inside a sentence [https://developer.android.com/reference/kotlin/androidx/compose/ui/text/style/TextDirection, 2026-11-28]
- Unconfirmed from primary sources: FSI/PDI rendering in Compose Text, and where TextAlign.Start puts an LTR-direction field in an RTL layout -> test with Force RTL layout direction
- Compose gives TalkBack a focus stop (isScreenReaderFocusable) to a node that merges descendants, or to an unmerged leaf with text, contentDescription or state and no merging ancestor; no click action or focusable() is needed [https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-main/compose/ui/ui/src/androidMain/kotlin/androidx/compose/ui/platform/AndroidComposeViewAccessibilityDelegateCompat.android.kt, 2026-11-28]
- clearAndSetSemantics sets isClearingSemantics, not merge: the node becomes a leaf holding your contentDescription, its own TalkBack stop unless an ancestor merges (a clickable card), then it is read inside the card's merged text [https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-main/compose/ui/ui/src/commonMain/kotlin/androidx/compose/ui/semantics/SemanticsModifier.kt, 2026-11-28]
