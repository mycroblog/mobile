# Lazy lists, refresh, preferences

- LazyColumn `items(key = ...)`: with a stable key the scroll position follows the first visible item when items are added or removed before it; `requestScrollToItem` on LazyListState overrides; keys must be Bundle-saveable [https://developer.android.com/reference/kotlin/androidx/compose/foundation/lazy/package-summary, checked 2026-11-28]
- `rememberLazyListState` saves only firstVisibleItemIndex and firstVisibleItemScrollOffset (not the key) via rememberSaveable; after process death the index is restored against whatever the list holds at first measure -> an anchor (item ID + offset) must be stored by us and applied with scrollToItem once the items exist [https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-main/compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/lazy/LazyListState.kt, checked 2026-11-28]
- `PullToRefreshBox(isRefreshing, onRefresh, state = rememberPullToRefreshState(), indicator)` in material3 (since 1.3.0, 1.5.0 stable); PullToRefreshDefaults.LoadingIndicator is experimental in 1.5.0; wraps a scrollable child such as LazyColumn(Modifier.fillMaxSize()) [https://developer.android.com/develop/ui/compose/components/pull-to-refresh, https://developer.android.com/jetpack/androidx/releases/compose-material3, checked 2026-11-28]
- Preferences DataStore 1.3.0 (`androidx.datastore:datastore-preferences`): one instance per file per process (else IllegalStateException); `by preferencesDataStore(name)` at file top level, or a `@Provides @Singleton` for Hilt; keep it in a repository, expose Flow through a ViewModel [https://developer.android.com/topic/libraries/architecture/datastore, checked 2026-11-28]
- DataStore files in files/datastore/ are in Auto Backup and device transfer by default; exclude via data_extraction_rules.xml if a chosen server must not follow the user [https://developer.android.com/topic/libraries/architecture/datastore, checked 2026-11-28]
